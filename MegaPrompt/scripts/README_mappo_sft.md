# MAPPO → SFT для одного агента

`build_mappo_sft.py` создаёт примеры имитационного обучения: один пример на живого агента и шаг успешного эпизода. На вход модели подаются общая инструкция, локальное наблюдение **до** действия, роль, наблюдаемое состояние команды и до пяти собственных предыдущих действий. Целевой ответ — записанное MAPPO действие в формате `<action>LEFT</action>`. Текст промпта формируется через `megaprompt.renders.Renderer` и шаблон `craftext_prompt/templates/mappo_sft/`.

Отсутствующие объяснения не генерируются. Это behavioral cloning, а не датасет обоснований: успешный исход всей команды не означает, что каждое отдельное действие оптимально. Наблюдения других агентов, будущие действия, награды и итог эпизода в prompt не попадают. Полный мир, диалог и результат последнего действия в этих данных не записаны. При генерации проверяются непрерывность шагов, уникальность `(trajectory_id, step_id)`, неизменность индексов задачи/инструкции и успешное завершение на последнем шаге. Неполные или неуспешные эпизоды исключаются. ID траектории определяет воспроизводимый split — все шаги и агенты одного эпизода попадают в одну выборку.

## Установка и запуск

Нужен Python 3.10+ с `numpy`, `pyarrow` и `pyyaml`. Также используются расположенные в соседних каталогах модули `MA-Craftax/baselines/trajectory_parquet.py`, `visualize_each_task.py`, `visualize_mappo_trajectory.py` (последний требует Pillow), а также исходники сценариев и констант. Можно установить зависимости в своё окружение:

```bash
python -m pip install numpy pyarrow pyyaml pillow
```

Сначала проверьте небольшой фрагмент:

```bash
cd /Users/igor/work/ma-craftext/MegaPrompt
python scripts/build_mappo_sft.py --max-shards 2 --output /Users/igor/work/HF/mappo_sft_sample
```

Для всего имеющегося набора:

```bash
python scripts/build_mappo_sft.py --skip-unreadable --output /Users/igor/work/HF/mappo_sft
```

При известной проверке `part_003730.parquet` не читался из-за повреждённого footer; флаг позволяет пропустить такие файлы, записав ошибки в `report.json`. Без флага скрипт прекращает работу при ошибке чтения. Пропуск части данных уменьшает покрытие; эпизоды с пропущенными шагами отбрасываются. Параметры `--parts`, `--scenario-file`, `--constants-file`, `--history`, `--seed`, `--val-fraction`, `--test-fraction` настраивают вход и разбиение; `--help` показывает значения по умолчанию. `--max-shards` предназначен для проверки и может оставить часть эпизодов неполными. Каталог вывода должен отсутствовать: так скрипт не перезапишет чужие результаты. Если выполнение прервано, выберите новый каталог или самостоятельно удалите неполный результат. Создание полной текстовой выборки и временного SQLite-индекса потребует времени и свободного места.

## Результат и ограничения

Файлы `train.jsonl`, `validation.jsonl`, `test.jsonl` содержат по объекту на строку:

```json
{"messages":[{"role":"user","content":"..."},{"role":"assistant","content":"<action>DO</action>"}],"metadata":{"trajectory_id":2,"step_id":0,"agent_id":0,"action_id":5}}
```

В реальных строках metadata также содержатся задача, инструкция, роль и исходная часть. Для обучения используйте `messages`, metadata — для анализа и аудита. `report.json` содержит число эпизодов и примеров, распределения действий, ролей и задач, таблицу имён и ID действий, настройки и ошибки чтения. Контролируйте дисбаланс действий и задач: split делается по траекториям, без гарантии равных долей шагов или представленности каждой задачи. Долгие эпизоды дают больше примеров. Перед обучением нужно отдельно решить, требуется ли их сэмплирование или балансировка.

Исходный `.meta.json` у этого набора отсутствует: тексты инструкций восстановлены из текущего `instructions.py`. Проверка согласованности индексов инструкции и задачи выявляет некоторые несовместимости, но не доказывает идентичность версии сценариев при сборе. В отчёте записываются SHA-256 файлов сценариев и констант. Схема декодера соответствует текущему `renderer_symbolic.py`, 3 агентам, локальной карте 9×11 и компактному наблюдению длиной 8746; для другого формата скрипт завершится ошибкой. Абсолютные координаты и невидимые клетки не восстанавливаются. Нормализация величин инвентаря и характеристик обратная преобразованиям текущего символьного рендерера; типы мобов показаны как класс и числовой ID, поскольку наблюдение не содержит их текстовых имён.

Для применения обученной модели во время игры нужен **тот же** шаблон и декодирование текущего наблюдения (`describe_obs`), такая же история и маска разрешённых ролью действий. Разрешение роли не гарантирует, что действие сейчас осуществимо в конкретном состоянии. Действия передачи названы `GIVE_TO_TEAMMATE_1` и `GIVE_TO_TEAMMATE_2`: это ID 52 и 53, адресаты в порядке номеров агентов без текущего агента; `REQUEST_PICKAXE` и `REQUEST_SWORD` — ID 54 и 55. `report.json` содержит полное отображение имён в ID для интеграции с окружением. Существующие шаблоны MegaPrompt с `<reasoning>` не совместимы с этим target без отдельной адаптации; фиктивные рассуждения здесь намеренно не создаются.
