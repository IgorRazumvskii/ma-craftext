# Создание SFT-датасета через Docker и Hugging Face

Docker-контейнер скачивает траектории из `igor69raz/ma-craftax-dataset`, проверяет эпизоды и по мере обработки загружает результат в новый или явно разрешённый пустой dataset-репозиторий HF. Требуется Docker с Compose и доступ сервера к Hugging Face; Conda и GPU на сервере не нужны.

## Запуск на сервере

После того как изменения закоммичены и отправлены в Git, в существующей копии проекта:

```bash
cd /путь/к/ma-craftext
git pull
cd MegaPrompt
```

Создайте локальный файл `.env` (он игнорируется Git) и ограничьте доступ к нему:

```bash
umask 077
nano .env
```

Содержимое файла:

```dotenv
HF_TOKEN=hf_ВАШ_ТОКЕН
SFT_OUTPUT_REPO=igor69raz/ma-craftax-llm-sft
```

Замените токен и при необходимости имя результата. Токену необходимы права чтения исходного репозитория и создания/записи dataset-репозитория в выбранном аккаунте. **Репозиторий назначения должен ещё не существовать**; по умолчанию он будет приватным. Токен передаётся контейнеру через окружение и доступен администраторам Docker; не коммитьте `.env` и не показывайте вывод `docker compose config`, содержащий подставленный токен.

Для уже созданного пустого репозитория, содержащего максимум служебный `.gitattributes`, дополнительно задайте `SFT_USE_EMPTY_REPO=1`. Его видимость сохранится прежней; наличие любого другого файла остановит запуск. Не запускайте параллельно несколько процессов записи в один репозиторий.

Запустите:

```bash
docker compose -f compose.sft.yaml up --build --exit-code-from sft
```

Compose соберёт CPU-образ, скачает исходные части, проверит их и отправит результат в HF. Процесс работает до завершения; код выхода `0` и сообщение `Completed: ...` означают успешный запуск. Если SSH-сессия может оборваться, удобнее запустить команду внутри `tmux` или воспользоваться фоновым режимом:

```bash
docker compose -f compose.sft.yaml up -d --build
docker compose -f compose.sft.yaml logs -f sft
```

Отключение от просмотра логов с `Ctrl+C` не останавливает контейнер. Проверить итоговый статус:

```bash
docker compose -f compose.sft.yaml ps -a
```

Ожидаемый результат — контейнер `Exited (0)` и `README.md` с `report.json` в новом HF-репозитории. `README.md` загружается после всех частей и отчёта; проверяйте и статус завершения. Не запускайте `up` повторно с тем же ID: существующий репозиторий защищён от перезаписи.

## Данные и настройки

Исходные Parquet и служебный кэш сохраняются на сервере в `MegaPrompt/sft-data/`; временный SQLite-индекс создаётся там же в `sft-data/tmp` и удаляется при штатном завершении. Результирующие JSONL-файлы формируются в памяти порциями и загружаются в HF. Нужны свободное место под исходные данные и индекс и оперативная память под три буфера JSONL. Созданные в контейнере файлы на сервере могут принадлежать root.

Необязательные параметры можно добавить в `.env`:

```dotenv
# Источник и снимок; по умолчанию используется актуальный main.
SFT_SOURCE_REPO=igor69raz/ma-craftax-dataset
SFT_SOURCE_REVISION=main
SFT_SOURCE_FOLDER=mappo_100k_20261101_210728/parts

# Публичный репозиторий: 1. По умолчанию 0 (приватный).
SFT_PUBLIC=0

# Использовать существующий репозиторий, только если он пустой.
SFT_USE_EMPTY_REPO=0

# Пропускать нечитаемые части с записью ошибок в report.json.
SFT_SKIP_UNREADABLE=1

# Примерный размер каждой выгружаемой части JSONL в МиБ.
SFT_SHARD_MIB=64

# Ограничение числа обрабатываемых частей для проверки; 0 — все.
SFT_MAX_SHARDS=0

# Каталог на сервере для входных файлов и временного индекса.
# SFT_WORK_DIR=/absolute/path/to/sft-data
```

По умолчанию пропускаются нечитаемые части: у локальной копии исходного набора обнаружен повреждённый `part_003730.parquet`. При `SFT_SKIP_UNREADABLE=0` обнаружение такой части прервёт запуск. Для тестирования на ограниченном числе частей используйте отдельный новый `SFT_OUTPUT_REPO`: будет создан полноценный, но неполный датасет. Сейчас скачивается весь выбранный исходный снимок даже при ограничении обработки.

Снимок исходного репозитория фиксируется по SHA в начале запуска. На диске каждому SHA соответствует отдельная папка, чтобы старые Parquet не попали в новый запуск; ревизия указывается в `report.json`. При HTTP 429 на этапе получения исходных файлов контейнер ждёт около пяти минут и повторяет попытку; при временных обрывах соединения, тайм-аутах и некоторых ошибках 5xx повторяет с увеличивающейся задержкой. Всего предусмотрено до 12 попыток на операцию. Ранее скачанные файлы снимка и их метаданные сохраняются. Для повторного запуска с тем же снимком, если `main` изменился, задайте `SFT_SOURCE_REVISION` равным SHA из лога. `SFT_WORK_DIR` должен обеспечивать достаточно места и прав на запись. `docker compose down` не удаляет этот каталог: при необходимости удалите его самостоятельно после завершения.

## Ошибки и повторный запуск

При ошибке на этапе скачивания выходной репозиторий ещё не создан. Если ошибка произошла во время преобразования или загрузки, на HF может остаться частичный репозиторий. Автоматическое продолжение выгрузки не реализовано: выберите **новый** `SFT_OUTPUT_REPO` либо самостоятельно удалите частичный репозиторий в настройках HF. Не считайте набор законченным только потому, что появились отдельные файлы.

Формат примеров и ограничения исходных данных описаны в [README_mappo_sft.md](README_mappo_sft.md). В частности, тексты инструкций восстановлены из текущего исходного кода сценариев, поскольку исходные метаданные датасета отсутствуют.
